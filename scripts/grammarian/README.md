# Грамматист: конвертер UD → дерево плана, датасет, сверка (этап 4.25)

Всё в этом каталоге — офлайн-инструменты данных; в бот (`src/`) они не входят и ничего в нём не меняют.
Запуск всегда с `PYTHONPATH=<репозиторий>/src` (в `.venv` стоит чужой editable-пакет; **не** использовать `python -I`).

| Файл | Что делает |
|---|---|
| `ud_to_tree.py` | CoNLL-U → дерево `thought_to_tree` v1 + цель (последовательность действий). Основной код. |
| `own_stream.py` | поток «свои читатели»: фраза → `analyze_structured_utterance` → `parse_proposition(tree=True)` → `thought_to_tree` (путь рантайма) + цель из токенов фразы |
| `build_dataset.py` | сборка `train/train_wide/dev/heldout_lemma/heldout_construction/bench_ud.jsonl`, `vocab.json`, `stats.json` |
| `export_paradigms.py` | `paradigms.json`: для каждой (лемма, pos) допустимые pymorphy морф-теги (маска тег-головы) |
| `compare_paths.py` | сверка двух путей (UD-конвертер и читатели бота) на одних текстах → `cross_check.json` |
| `alt_orders.py` | альтернативные эталоны: перестановки единиц фразы, которые читатели бота читают в то же дерево (стенд и dev/heldout) |
| `prep_forms.py` → `prep_forms.json` | алломорфы предлогов (в/во, с/со ...): список решений по первым буквам следующего слова, выучен из корпусов |

| `evaluate_export.py` | локальный измеритель экспорта из Colab: слова по `words()`, верность читателем бота, сравнение с `realize_thought`, ворота (этап 4.27) |

## Формат (как в `src/debilgi/language/plan_tree.py`, версия 1)
Дерево: `nodes` (`id, lemma, pos, lex, role, head`, опц. `preposition`, `marker`, `elided`, `case_constraint`) и `clause`
(`move, focus, negated, negation_node, mood, tense, response_polarity, subject_elided, predicate_class`).
Сообщение из нескольких клауз: `{"kind":"message","clauses":[{"link":{"type","head_clause"},"id",...}]}`.
Список узлов — в каноническом порядке ролей (сначала сказуемое, затем аргументы сказуемого по роли, затем аргументы вложенных слов;
после каждого аргумента — его модификаторы/постмодификаторы), порядок слов предложения в нём не виден (тест
`test_node_list_carries_no_word_order`). Падеж, лицо/число глагола, род прилагательного и порядок во вход **не** подаются.

**Цель** — список действий в порядке слов предложения:
`["C", ptr, tag]` (взять узел `ptr` — сквозной индекс по всем клаузам по порядку — в форме `tag`), `["F", слово, лицензия]`
(слово закрытого класса; лицензия `preposition|marker|link|particle_negation|particle_conditional|particle_polar|conjunction:<узел или клауза>`),
`["P", знак]`. `tag` — отсортированные граммемы pymorphy (`"nomn,sing"`, `"1per,pres,sing"`, `INFN`, `"-"` — неизменяемое слово).
Слова в нижнем регистре, ё → е. Узлы без слова в поверхности (`elided` подлежащее, нулевая связка в настоящем времени) в цели не стоят.
Каждая форма проходит круговую проверку `inflect(лемма, tag) == слово` (pymorphy); не воспроизвелась — предложение отбрасывается.

## Маппинг UD → план
| UD | План |
|---|---|
| `nsubj`, `nsubj:pass` | `subject` (нет подлежащего у 1/2 лица → `elided` я/ты/мы/вы; иначе — отказ `verb_without_subject`) |
| `obj`, `iobj` | `direct_object`, `indirect_object` |
| `obl` + предлог из `_LOCATION_PREPOSITIONS` проекта; любой другой предлог | `location`; `topic` (как в рантайме: `parse_proposition` называет `topic` всякое не-локативное предложное дополнение); без предлога — `oblique` (*расширение*) |
| `advmod` ADV (Int: почему/зачем → `cause`, где/куда/откуда → `location`) | `manner` / роль по слову; Int → `focus` |
| `xcomp` VERB.Inf | `action_complement` (его `obj/obl/advmod` получают `head` = этот узел) |
| `xcomp`/корень + `cop` быть | `action_complement`=быть + `predicate_complement` с `head`=быть; на корне — сказуемое быть (copular), в настоящем времени без слова |
| `mark/case/cc` «как/словно/будто/точно» + NP | `comparison` + `marker` (слово «как» — `["F","как","marker:<узел>"]`) |
| `case` ADP | `node.preposition` (лицензия `preposition`); многословные предлоги — отказ |
| `amod`, `det`, `nummod`, `advmod` у NP | `modifier` (рекурсивно); `nmod/appos/flat/compound` → `postmodifier` |
| `PART не/ни` | `negated` + `negation_node` (второе «не» — отказ `double_negation`) |
| `PART бы/б` | `mood=conditional`; `PART ли` или «?» в конце → `move=polar_question` |
| `PronType=Int` | `move=slot_question`, `focus` = слово (для «какой N» — узел N) |
| `Mood=Imp` | `mood=imperative`, `move=command` |
| `conj` (клауза) / `advcl` (если→`condition`, потому/поскольку→`cause`, иначе `adverbial`) / `ccomp` (`complement`; с вопросом → `embedded_wh`/`embedded_polar`) | клаузы со связями; слово связи — `["F",…,"link:<клауза>"]` |
| прочие PART (тоже, только, даже, вот, же…) | узел `role=particle` (копируется как слово; *расширение*) |
| `conj` внутри NP + `cc` | узел `role=conjunct`, `["F","и","conjunction:<узел>"]` (*расширение*) |

**Расширения формата сверх рантайма 4.24** (рантайм-читатели их не создают; планировщик этапа D должен либо научиться их задавать, либо
сеть обучается на них зря): роли `oblique`, `particle`, `conjunct`; связи `adverbial`, `complement`; эллипс подлежащего только для 1/2 лица.

**Отказы** (`stats.json → rejects_ud`): длина > 25 слов, латиница/цифры/символы/междометия, фрагменты без подлежащего,
придаточные определительные/причастные обороты (`acl`), парataксис, вводные/вокатив, соединитель в начале главной клаузы
(`unlicensed_func:connective_on_main`: ни одна связь плана его не лицензирует), «быть» как вспомогательный (будущее/пассив),
глагол без выраженного подлежащего в 3 лице/прошедшем (род/число неизвестны), нерешённые круговой проверкой формы.

## Датасет
Правила (см. docstring `build_dataset.py`): дедупликация по грубому скелету (`predicate_class|вид|negated|mood|роли`, как в
`build_bench.py`, + связи) ≤ 30 на скелет **в каждом потоке отдельно**; `train_wide` — то же по тонкому скелету
(роли+теги+служебные в порядке цели); held-out леммы — существительные/глаголы с `digest("L:"+лемма) % 10 == 0`
(местоимения/прилагательные не исключаются: «мы», «вы» подпадают под правило); held-out конструкции — `comparison`
и `modal_be_predicate`; тест-файлы UD → только `bench_ud` (срезы стенда), dev-файлы → `dev`; из обучения исключены фразы стенда
`bench.json` (по тексту и по набору лемм). Таиговые `train-a…e` (≈119 тыс. предложений, README описывает 3 138 золотых) считаются серебром — это вывод, не документированный факт.


## Формат v2 (этап 4.27, LAST_MESSAGE43)
Изменения против §«Формат» выше (причины — LAST_MESSAGE42):
* **Вход.** `case_constraint` у именных групп (`np()` конвертера; длинные имена рантайма: `nominative`...), в обучении скрывается у 25 % узлов;
  `lex.gender` у я/ты/вы (по согласуемому слову того же клауза: прошедший глагол, краткое прилагательное), `lex.degree=comparative`, `lex.form=short`
  (по тегу цели: `annotate_from_target`); `clause.end` главной клаузы — `.`/`!`/`?`/`…`/`none`.
* **Цель.** Предлог — свойство узла (`node.preposition`), действия `F preposition:*` из цели убраны: `finalize_target` проверяет, что он стоял прямо перед
  первым словом поддерева узла, и что его поверхность — `preposition_form(лемма, следующее слово)`; иначе отказ (`preposition:*`). Последовательные слова
  одной лицензии — одно действие-фраза (`["F","потому что","link:1"]`). Концевой знак — из цели в `clause.end`; ведущее тире отбрасывается; внутренние знаки:
  не подряд, не терминальные, в пределах `punct_capacity` (запятые `2·(клаузы−1) + однородные + ряды модификаторов + 1`, пара тире, одно двоеточие; на 18,7 тыс. строк нарушали 0,14 %).
* **Поток «свои читатели».** Концевой знак — по соглашению рантайма (`?` у вопроса, иначе `.`), а не шум чата; ведущее «-» убирается; добавлен источник —
  фразы seed-диалогов (`toloka_seed.jsonl`) без диалогов, давших фразы стенду; потолок на скелет для этого потока 150 (доля в `train` 21,5 %).
* **Разбиения.** `comparison`: 4 из 5 строк train-файлов без held-out лемм (по хешу текста) — в `train`, остальное и все строки dev/test-файлов — в оценку;
  `modal_be_predicate` целиком в `heldout_construction` (ворота). Словари (`vocab.json`) и теги (`paradigms.json`) — только из train/train_wide.
  Dev/heldout-строки получили `alt_texts`/`alt_targets` (до 24 перестановок, принятых читателями).
* Тесты: `tests/unit/test_ud_to_tree_425.py` (в т. ч. новые `test_v2_*`).

## Формат v3 (этап 4.29, LAST_MESSAGE45; план — LAST_MESSAGE44 §5)
Изменения против §«Формат v2» (все — офлайн-данные; рантайм `src/` не менялся, поэтому у адаптера этапа D есть новые обязанности — они перечислены ниже):
* **Слова закрытого класса — вход.** `finalize_target` пишет в дерево `clause.func = [[вид, слово], ...]` (вид: `link` — связь клаузы,
  `particle_negation` — «не»/«ни», `particle_conditional` — «бы»/«б», `particle_polar` — «ли») и `node.func = [["conjunction", "и"]]` у
  члена ряда. У каждой клаузы список есть всегда (возможно пустой): так v3-дерево отличается от v2. Сеть ставит ровно эти фразы и ровно по разу,
  выбирать слово со смыслом ей нечем. **D: план сам задаёт слово связи (а/но/и/хотя/когда/чтобы/если/потому что), сочинительный союз и «не»/«бы»/«ли».**
* **Маркер сравнения — свойство узла** (как предлог): `["F", маркер, "marker:k"]` из цели убран, `finalize_target` проверяет, что он стоит перед
  первым словом группы (перед предлогом узла) и равен `node.marker`; `realize` ставит его сам. Фиксированные выражения «как раз», «как бы», «как и»,
  «как будто» — не сравнение: один узел `role=particle` (многословная лемма, тег `-`; `Builder.node(merge_fixed=True)`).
  `node.marker_kind`: `comparison` (группа выделена запятыми) / `as_role` (без запятых) — признак для запятой; **D всегда подаёт `comparison`**.
* **`node.conj_rank`** — место члена в перечислении (1, 2, …; первый член неявно 0), `rank_conjuncts`.
* **`node.given`** — лемма узла была в 3 предыдущих предложениях того же документа (`Sentence.context`); ключа нет, когда документ неизвестен
  (GSD, `taiga-*`-идентификаторы: неизвестное — не «новое»). Читательский поток (`own_stream`) данности не знает. **D: данность — из контекста диалога.**
* **Падеж прилагательной/причастной именной части** (`predicate_complement`) — `case_constraint` из тега текста (`np()`; в читательском потоке —
  `annotate_from_target`). **D: подавать только падеж, который план сам зафиксировал (`ConceptArgument.grammatical_case`), а не вывод `_case_for_role`
  (измерено в 4.28: правило хуже «скрыт»); именную часть — по времени: настоящее — именительный, иначе творительный (по корпусу).**
* **Род существительного** — из текста (`Gender` токена), а не из словаря лемм: словарь давал «Люда», «Александра», «Пекка» другой род, и эталон противоречил
  собственному входу. Род «я/ты/вы» по-прежнему из согласуемого слова клауза; **D: род «я» брать из самофакта бота (мужской), «ты» — из личных
  фактов собеседника; неизвестный род — неполнота плана.** В обучении у 50 % узлов я/ты/вы род скрывается.
* **Чистка противоречий** (`check_consistency` = `plan_fidelity.check`, без `cc`): строка, чьё эталонное предложение противоречит собственному плану
  (несогласованное подлежащее/сказуемое, прилагательное с чужим падежом, «не» не перед своей группой, разорванная именная группа с невербальной
  вершиной), — `Reject('inconsistent:<виды>')`. Читательский поток дополнительно сверяется с UD там, где UD-конвертер тоже прочитал эту фразу
  (`attachment_edges`: пары «лемма — лемма главы»); расхождение — `own:contradicts_ud`. Падеж при синкретизме («очередь» — им./вин.) в читательском
  потоке берётся из ограничения плана, если слово то же (`_fixed_case_tag`). Цифры — `stats.json` (`rejects_ud`, `rejects_own`).
* **`plan_fidelity.py`** — «верность по плану», измеримая на 100 % строк: падеж плана, лексические граммемы, согласование, «не», связность именных групп,
  слова закрытого класса. На эталонных целях всех сплитов даёт **0 срабатываний** (`.codex_work/grammarian_diag4/gold_violations.py`).
* **Измеритель** (`evaluate_export.py`): `words()` без тире (`alt_orders.words`; дефисные слова сравниваются по частям); верность по плану; стенд «own» в двух
  режимах (падеж как прочитал читатель / **падежа нет**) против `realize_thought` в том же режиме (`bench_v2.py run --no-case`); `--notebook` — ноутбук, обучавший
  экспорт (для переоценки v2).
* Тесты: `tests/unit/test_grammarian_v3_429.py`.
